## 2. Critical Bugs & Logic Issues

### 2.1 NEW — Plaintext password logged to console on a common password pattern
**Severity: High (secret leakage into logs)**
`testing-core/src/presentation/authentication/authValidation.ts:61-65`, inside
`sanitizeString()`:
```ts
// Check for potential NoSQL injection patterns
if (value.includes('$') && value.match(/\$\w+/)) {
  console.error(`[Auth] Potential NoSQL injection in ${fieldName}:`, value);
  return null;
}
```
This function is called as `sanitizeString(password, 'password')` from both
`authSignupController.ts:21` and `authLoginController.ts:22`. Any password containing a
`$` immediately followed by a word character — e.g. `Correct$Horse1`, a pattern users are
routinely told to use for "strong" passwords — trips this branch and logs the **raw
plaintext password** to the server console via `console.error`, which typically flows
into log aggregation/monitoring infrastructure. This is not a NoSQL-injection payload in
that case; it's an ordinary password being misclassified and exfiltrated into logs.

Adjacent, lower-severity: `authLoginController.ts:34`:
```ts
console.log(`[Auth] Password length: ${sanitizedPassword?.length}`);
```
logs password-length metadata unconditionally on every login attempt — not the secret
itself, but still password-derived data that has no reason to be in logs.

### 2.2 NEW — Confirmed bugs are silently dropped when a run is cancelled
**Severity: Medium (data loss in the product's own core value — losing discovered bugs)**
`testing-core/src/infrastructure/playwright/PlaywrightBrowserEngine.ts`:
- `stop()` (≈L84-91): sets `cancelledDuringRun = true`, calls `this.activeEngine.stop()`,
  then **nulls the reference**: `this.activeEngine = null;` (L91).
- `run()`'s `finally` block (L249): `this.capturedConfirmedBugs =
  this.activeEngine?.getConfirmedBugsFromMemory() ?? [];`

Because `stop()` (invoked by the `/api/safari/stop` route, asynchronously, while `run()`
is still awaiting the engine at L227) nulls `activeEngine` *before* `run()`'s own
`finally` block executes, every cancelled run's `capturedConfirmedBugs` optional-chains
to `undefined` and falls back to `[]` — even if the engine had already found and recorded
real confirmed bugs earlier in the session. `getConfirmedBugs()` (L272) then always
reports an empty list for any manually-stopped run. This is a correctness regression
risk introduced by (or at least not caught by) the `cancelledDuringRun` fix in Phase 2 —
the cancellation-detection fix (item 2.3 below) is correct, but the surrounding
teardown ordering has this independent bug.

### 2.3 Cancellation detection — CONFIRMED FIXED, now precise
`PlaywrightBrowserEngine.ts:33` (`private cancelledDuringRun = false;`), set `true` in
`stop()` before teardown, reset `false` at the top of every `run()`, and checked
explicitly in the catch block before deciding whether to swallow the error or rethrow it.
This replaces the prior overly-broad `TypeError` + message-substring match; unrelated
null-derefs now correctly propagate instead of being misreported as clean stops.

All five re-verified directly against current code (not taken from `plan.md`):

### 3.2 Correction to the prior review — `ActionRecorder` is NOT dead code
The original `REVIEWS.md` claimed `infrastructure/monitoring/actionBuffer.ts`'s
`ActionRecorder` duplicated `lib/circularBuffer.ts` with "zero callers" implied. This is
**wrong** on the zero-callers point: `ActionRecorder.recordStep(...)` is called from
`domain/scenarios/formBypasser.ts:265` and `domain/scenarios/rapidClicker/buttonSpammer.ts:75`,
both of which are wired into the live hot path via `domain/services/exploration/ActionExecutor.ts`.
The two buffers serve different call sites, not one superseding the other. What remains
true and unaddressed: `ActionRecorder` still evicts via
`while (this.records.length > this.capacity) { this.records.shift(); }` (`actionBuffer.ts`,
both in `record()` and `recordStep()`) — an O(n) reimplementation of the O(1) ring-buffer
logic `lib/circularBuffer.ts` already provides for `ExplorationEngine`'s own breadcrumb
buffer. Impact is minor (capacity defaults to 20), but it's genuine unaddressed
duplication, not dead weight — plan.md's Phase 3 item 14 ("replace with circularBuffer or
delete") should be re-scoped to "migrate, don't delete."

## 7. Prioritized Roadmap

Ordered by blast radius: correctness/security first, cosmetic last. Each item is
independently verifiable via the file:line citations above. This section describes
*what* needs fixing and *why* — no fixes are proposed inline.

1. **Fix password/credential leakage into logs** — `authValidation.ts:61-65`'s NoSQL-
   injection heuristic misfires on ordinary passwords containing `$word` patterns and
   logs them in cleartext; `authLoginController.ts:34` logs password length
   unconditionally. Highest priority: live, ongoing secret exposure on every login/signup
   that happens to match the pattern.
2. **Fix confirmed-bugs data loss on cancelled runs** — `PlaywrightBrowserEngine.ts`'s
   `stop()` nulls `activeEngine` before `run()`'s `finally` reads
   `getConfirmedBugsFromMemory()` from it, so every manually-stopped session reports zero
   confirmed bugs regardless of what was actually found. Undermines the product's core
   value on the exact path (manual stop) an operator is most likely to use mid-session.
3. **Resolve `MongoFindingRepository.collectBugFindings`'s dead-but-correct userId
   filter** — either wire it into a real route (verifying the `userId` source is
   trustworthy at the call site) or remove it; leaving a security-relevant filter
   unreachable is a latent trap for a future caller who assumes "it has tests/a filter,
   so it's safe" without re-checking.
4. **Dead-code removal batch (backend)** — `domainGuard.ts`, `runController.ts`,
   `stackManager.ts`, `socketServer.ts` (`TelemetryHub`) confirmed zero live callers;
   `TaskQueue.ts`/`SafariWorker.ts`/`worker-entry.ts` confirmed to have no live entry
   point anywhere, including Docker. Confirm intent with the user before deleting the
   BullMQ pipeline specifically (may be intentional future infra), otherwise safe to
   remove as a bundle.
5. **Dead-code removal batch (frontend)** — `designs/{SlidingAuthForm,GradientBlinds}.tsx`,
   `designs/components/{MagicBento,FlowingMenu,CircularGallery,ChromaGrid}.tsx` (+CSS),
   `components/telemetry/TelemetryStream.tsx`, `infrastructure/socket/BinaryFrameReceiver.ts`
   (+ the dead `useBinaryStream` branch in `LiveFeed.tsx`). Remove `gsap` and
   `dompurify`/`@types/dompurify` from `developer-dashboard/package.json` in the same
   pass (unused now/after this cleanup).
6. **Migrate `ActionRecorder` onto `lib/circularBuffer.ts`** — it is alive (do not
   delete), but still reimplements O(n) shift-based eviction that the ring buffer already
   solves elsewhere in the same codebase. Re-scope plan.md's old Phase 3 item 14 from
   "delete" to "migrate."
7. **Collapse `ChaosTransactionManager` aliases** — `startTransaction`/`endTransaction`
   are real duplication (not dead code) with 7 live call sites; consolidate onto
   `openTransaction`/`closeTransaction`.
8. **Remove duplicate `decodeTokenExpiration`** in `useDashboardController.ts`; import
   from `tokenUtils.ts` (never executed from the original Phase 3 list).
9. **Add unit tests for security-critical, currently-untested code** — all of
   `presentation/authentication/*.ts` (zero coverage today, and is where the §2.1 bug
   lives), `ExplorationLoop.ts`'s extracted step methods, `pathfinder/{GraphStore,EdgeSelector}.ts`
   in isolation, and `developer-dashboard`'s `authRefresh.ts` retry-on-401 path.
10. **Adopt a real test runner wired into `npm test`/CI** — current tests are ad-hoc
    `tsx`-executed scripts with no automatic enforcement; a regression in any covered
    module (perceptron, circularBuffer, TOCTOU, characterization) currently only fails if
    someone remembers to run it manually.
11. **Correct the `StateGraphNavigator` facade's understated dead-surface count** (11,
    not 9, public methods with no production caller) before it's cited again as
    justification for keeping the full 19-method surface.
12. **Align TypeScript version across workspaces** (`^5.8.3` in `testing-core` vs.
    `~/^5.7.0` elsewhere) — same category as the mongoose skew already fixed in Phase 6.
13. **Cosmetic cleanup** — `authPasswordResetController.ts:202` should reference its own
    `APP_URL` constant instead of re-deriving the literal; extract `ExplorationLoop.ts`'s
    inline `RunContext` magic numbers into named constants matching the
    `pathfinder/config.ts` pattern; remove the stale "FIX:" debugging comments in
    `authConfig.ts:109,117,123`.
