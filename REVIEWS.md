# BugSafari — Codebase Review

> Generated by structural + deep-logic audit. Read-only analysis, no source files modified.

## 1. System Purpose & Functionality

**BugSafari** is an autonomous exploratory testing engine for Single-Page Applications. Instead of scripted test cases, it drives a headless **Playwright** browser through a target SPA, deciding what to click next using a **single-layer Perceptron** (Delta Rule) that scores candidate DOM elements. **Structural DOM Hashing** fingerprints page state to avoid re-exploring the same screen (loop prevention). A **20-step Circular Action Buffer** records the most recent actions so that when a crash, console error, or unhandled exception is detected, the engine can show the exact sequence that caused it. Heuristic **data fuzzing** stresses form inputs with boundary/adversarial values.

### Monorepo layout (npm workspaces)
| Package | Role | Port |
|---|---|---|
| `developer-dashboard/` | React 19 + Vite "Watchtower" operator console | 5173 |
| `testing-core/` | Node/Express + Socket.IO + Playwright engine | 3000 |
| `shared/` | Strict TS contracts (`shared/types/{telemetry,bug,testingType,regression}.ts`) barrel-exported via `shared/types.ts` | — |
| `backend/` | **Orphaned** — contains only `node_modules`, no source, not in workspaces list. Stale scaffold. |

> Note: CLAUDE.md states "React 18/Vite" but `developer-dashboard/package.json` pins `react@^19.2.5` — documentation is out of date relative to the actual dependency.

### Primary data flow
1. Operator authenticates (JWT via `authController.ts`) or continues as guest (unauthenticated, results not persisted).
2. Dashboard calls `POST /api/start-test` → `registerRoutes.ts` → `StartExplorationUseCase.execute()`.
3. Use case spins up `PlaywrightBrowserEngine`, which drives `ExplorationEngine` / `ExplorationLoop` / `StateGraphNavigator` (domain layer) using the perceptron (`ml/perceptron.ts`) to rank candidate elements and `domHasher.ts` to detect already-seen states.
4. Every action, screenshot frame, and detected fault streams live to the dashboard over Socket.IO via `SocketTelemetryGateway` → `registerSocketHandlers.ts` → dashboard's `SocketConnectionManager`.
5. On crash detection, the last 20 buffered actions (`lib/circularBuffer.ts`) are attached to a `Finding`, optionally persisted to MongoDB via `MongoFindingRepository` (authenticated users only).
6. Dashboard renders live telemetry (`components/telemetry`), perceptron scores, forensics/crash detail (`components/forensics`), and run history (`components/history`).

### Architecture pattern
Both `testing-core` and `developer-dashboard` follow a clean-architecture-ish layering: `domain/` (entities, services, scenarios, fuzzing, chaos) → `application/` (use cases, ports, services) → `infrastructure/` (Playwright, Mongo, Socket.IO, queue/workers) → `presentation/` (Express routes, Socket handlers, auth). In practice this layering is only partially honored (see §2/§3) — several infrastructure/application modules exist with no callers, meaning the "primary" execution path bypasses layers the architecture diagram implies are load-bearing.

## 2. Critical Bugs & Logic Issues

### testing-core (backend engine)
1. **`presentation/api/registerRoutes.ts:188-197` + `application/useCases/StartExplorationUseCase.ts:277-319`** — TOCTOU race on the singleton use case. `isActive()` is checked synchronously, but `execute()` only flips `state.active = true` after several `await import(...)` calls. A second `POST /api/start-test` in that window bypasses the guard, overwrites `setUserId()`, and runs two overlapping Playwright sessions against shared state.
2. **`presentation/authentication/authController.ts:519,599-603`** — password-reset token is stored in **plaintext** and compared with `!==` (non-constant-time), unlike the bcrypt login path. DB read exposure or timing attack yields a usable reset token.
3. **`infrastructure/database/repositories/MongoFindingRepository.ts:416-424`** — `collectBugFindings(targetUrl)` filters only by URL, no `userId`, unlike every sibling query. Currently unreferenced (dead), but a live cross-tenant data leak if ever wired up.
4. **`infrastructure/playwright/PlaywrightBrowserEngine.ts:220-231`** — catches "session terminated" by matching `TypeError` + a message substring. This will also swallow unrelated null-deref bugs elsewhere and misreport real crashes as graceful stops.
5. **`presentation/api/registerRoutes.ts:146-172`** — `POST /api/safari/stop` has **no authentication** ("emergency cleanup" rationale), letting any unauthenticated client stop another operator's run.
6. **`presentation/authentication/authConfig.ts:30-34`** — hardcoded dev `JWT_SECRET` fallback with no runtime warning if `NODE_ENV` is unset (`isDevelopment` defaults `true`), so a misconfigured deployment can silently run with a well-known secret.
7. **CORS**: `index.ts:21` (`cors()` reflects any origin) + `index.ts:26` (Socket.IO `origin: '*'`) with JWT bearer auth and no documented rationale — any origin can hit authenticated endpoints if a token leaks via XSS.
8. **Dependency version skew**: root `package.json` pins `mongoose@^9.6.3`, `testing-core/package.json` pins `mongoose@^8.24.0`, and root devDependency `@types/mongoose@^5.11.96` is three majors behind either. Type-checking against stale types risks masking real API mismatches.

### developer-dashboard (frontend)
1. **`context/AuthContext.tsx:372-375`** — `refreshToken()` is fully implemented but **never called anywhere**; sessions rely solely on hard 401 → logout. Silent-refresh is dead code, not a working feature.
2. **`application/useCases/useRegressionVerifier.ts:37-48`** — socket is cached with the JWT read once at creation; if the token changes later (login/refresh/guest→auth), the open verification socket keeps replaying the stale token indefinitely.
3. **`App.tsx:45`** and elsewhere — reads `localStorage.getItem('bugsafari_token')` directly instead of `useAuth().token`; no `storage` event listener exists anywhere, so logout/login in another tab isn't reflected until the next failed request.
4. **`services/historyService.ts:28-31`** — logs a 20-character JWT prefix to the console on every authenticated request — partial token material leaks into devtools history / session-replay tools.
5. JWT stored in `localStorage` (not httpOnly cookie) across `AuthContext.tsx`, `historyService.ts`, `useRegressionVerifier.ts` — standard SPA tradeoff, but no CSP evident in source, so any future XSS has direct token exfiltration.

## 3. Code Duplications & Refactoring Targets

### testing-core
- **~230 lines of dead parallel infrastructure**: `infrastructure/monitoring/socketServer.ts` (`TelemetryHub`), `application/services/domainGuard.ts`, `runController.ts`, `stackManager.ts` (`PageStackManager`) have **zero call sites** anywhere in `src/`. Real pause/resume/stop lives in `ExplorationEngine` + `registerSocketHandlers.ts`; real telemetry lives in `SocketTelemetryGateway`. This duplicate subsystem should be deleted or wired in — not left as silent dead weight.
- **Unused job-queue pipeline**: `infrastructure/queue/TaskQueue.ts` + `infrastructure/workers/SafariWorker.ts` + `worker-entry.ts` re-implement the same `StartExplorationUseCase` invocation as the direct HTTP path in `index.ts`, but `TaskQueue.addSafariTask` has no callers. A second execution path that must be hand-synced with the primary one but currently isn't exercised at all.
- **Two circular-buffer implementations**: `infrastructure/monitoring/actionBuffer.ts` (`ActionRecorder`) reimplements "keep last 20" via `push` + `shift` (O(n) per record) duplicating the purpose-built O(1) `lib/circularBuffer.ts` already used by `ExplorationEngine.ts:63` for the identical requirement.
- **Divergent duplicate interfaces**: `authMiddleware.ts:4-8` and `authController.ts:148-151` each declare their own `AuthRequest` interface; the latter is unused and missing `isGuest`, risking silent drift.
- **Oversized files/functions** (SRP violations): `domain/services/StateGraphNavigator.ts` (1295 lines), `presentation/authentication/authController.ts` (630 lines), `domain/services/exploration/ExplorationLoop.execute()` (~540-line single method mixing stagnation scoring, telemetry, pathfinding, and action execution).
- **Redundant API surface**: `domain/chaos/ChaosTransactionManager.ts:245-257` — `startTransaction`/`endTransaction` are pure aliases of `openTransaction`/`closeTransaction`.
- Pervasive unconditional `console.log`/`console.error` (with emoji prefixes) logging full request bodies/session internals in `registerRoutes.ts` and `MongoFindingRepository.ts` — no log-level gating.

### developer-dashboard
- **`designs/` folder is mostly dead code**: `LandingPage.tsx` and `ThemeContext.tsx` are wired into `App.tsx`, but `SlidingAuthForm.tsx`, `GradientBlinds.tsx`, and `designs/components/{MagicBento,FlowingMenu,CircularGallery,ChromaGrid}.tsx` (+ CSS) have zero external references. `SlidingAuthForm.tsx` duplicates the live login/signup flow in `components/auth/{LoginForm,SignupForm}.tsx` — two competing, one unreachable.
- **`infrastructure/socket/BinaryFrameReceiver.ts`** (~450 lines, full binary WebSocket frame protocol + `LiveFeedRenderer`) is dead in production — its `useBinaryStream` flag defaults `false` and is never passed `true` by its sole caller. The actual live-frame path is Socket.IO base64 `live-frame` events.
- **`components/telemetry/TelemetryStream.tsx`** — a full alternate telemetry renderer with no importers, duplicating logic already inline in `ClinicalForensicsDashboard.tsx`.
- **Auth-header construction reimplemented 4+ times** independently (`AuthContext.tsx`, `useUserSettings.ts:getAuthHeaders`, `historyService.ts:getAuthHeaders`, `useRegressionVerifier.ts`) instead of one shared helper — all read the same `'bugsafari_token'` key directly rather than going through `AuthContext`.
- **Duplicate JWT-decode utility**: `useDashboardController.ts:56-65` reimplements `tokenUtils.ts:11-19`'s `decodeTokenExpiration` verbatim, unused in the file that duplicates it.
- **`EngineGateway.removeAllListeners()`** implemented at all three layers but never called by any consumer — should be wired into unmount cleanup or removed.
- **`components/icons/index.ts`** is a pure re-export shim into `designs/icons/` — production icons physically live inside the "legacy landing page" folder.
- Root-level documentation clutter: `ALL_FILES_CODEBASE.md`, `BUGSAFARI_BLUEPRINT.md`, `CODEBASE_DOCUMENTATION.md`, `SETTINGS_CODE_REVIEW.md`, `implementation_plan.md`, `MONGO_VIEW_DATA.md`, `TESTING_TYPES.md`, `SETUP_DISTRIBUTED.md` — eight overlapping root markdown files with unclear ownership/authority versus `CLAUDE.md` and `README_LOCAL_DEV.md`.
