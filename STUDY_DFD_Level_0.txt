========================================================================
BUGSAFARI THESIS DEFENSE STUDY GUIDE
TOPIC: DATA FLOW DIAGRAM - LEVEL 0 (CONTEXT DIAGRAM)
========================================================================

--------------------------------------------------------------------
1. WHAT IT REPRESENTS
--------------------------------------------------------------------
The Level 0 Data Flow Diagram, also called the Context Diagram, is the
highest-level view of BugSafari. The whole system is drawn as a SINGLE
process (a circle labelled "0 BugSafari"), and everything outside it is
drawn as an external entity.

The point of this diagram is to show what ENTERS the system and what
LEAVES it, without saying anything about how the work is done inside. It
answers "who talks to BugSafari, and what data crosses the boundary".


--------------------------------------------------------------------
2. PURPOSE AND IMPORTANCE IN BUGSAFARI
--------------------------------------------------------------------
It defines the system boundary. Before you can design what happens inside,
you must agree on where the system starts and stops, who its users are,
and which outside services it depends on. This diagram fixes that scope on
a single page, so every later, more detailed diagram must line up with it.


--------------------------------------------------------------------
3. THE FIVE EXTERNAL ENTITIES (WHAT EACH MEANS)
--------------------------------------------------------------------
BugSafari has five external entities: two are people, one is the website
being tested, and two are outside services the system calls when needed.

  Tester        - A registered user who signs in, starts test runs, and
                  reviews saved reports. The person using BugSafari, not
                  part of it.
  Guest Tester  - A visitor who runs a test without signing up. Same role
                  as a Tester, but nothing is saved for them.
  Target Web App- The website the tester wants checked. Owned by someone
                  else; BugSafari only visits it.
  AI Advisor    - Google Gemini, asked for a written fix suggestion. A
                  paid service outside the codebase.
  Email Service - An SMTP mail server. Only used to deliver password reset
                  links.


--------------------------------------------------------------------
4. THE FLOW OF DATA (WHAT CROSSES THE BOUNDARY)
--------------------------------------------------------------------
Reading the arrows in and out of the single BugSafari process:

  Tester        -> System : login details, target URL, test settings
  System        -> Tester : live test progress, bug findings, saved reports

  Guest Tester  -> System : target URL, test settings
  System        -> Guest  : live test progress, bug findings
                            (NO saved reports for a guest)

  System        -> Target Web App : page requests, clicks, typed input
  Target Web App-> System          : page content, console errors,
                                      failed requests

  System        -> AI Advisor : bug details and page context
  AI Advisor    -> System     : suggested fix

  System        -> Email Service : password reset link

Meaning of the main flows:
  * Login details          - email and password, exchanged for a token.
  * Target URL and settings- the address to test, plus which attack types.
  * Live test progress     - a running stream of steps, screenshots,
                             errors.
  * Bug findings           - each problem found, with the steps that
                             caused it.
  * Saved reports          - past-run reports pulled from storage
                             (Tester only).
  * Clicks and typed input - the actions the engine performs in a real
                             browser.
  * Page content and errors- what the browser sees back after each action.
  * Bug details            - sent to the AI only when the tester asks.
  * Password reset link    - sent only during account recovery.


--------------------------------------------------------------------
5. HOW THE COMPONENTS INTERACT
--------------------------------------------------------------------
The Tester and Guest give input (URL, settings, credentials) and receive
live output (progress, findings). BugSafari drives the Target Web App like
a real user and reads back what the browser sees. Two outside services are
called only on demand: the AI Advisor when a fix is requested, and the
Email Service during password recovery.


--------------------------------------------------------------------
6. WHY THE DESIGN WAS CHOSEN (KEY DECISIONS)
--------------------------------------------------------------------
  * Guest drawn SEPARATELY from Tester: the system treats the two roles
    differently. A guest can run a full test and watch it live, but the
    run is never written to storage, so a guest has no reports to return
    to. Showing them as two entities makes that difference explicit.

  * AI Advisor is OPTIONAL: if no API key is set, BugSafari answers from a
    built-in fix catalog instead, and the rest of the system works the
    same. It is drawn as external because it is a separate paid service.

  * Email Service is minimal: it exists on the diagram only to carry
    password reset links, nothing else.


--------------------------------------------------------------------
7. POSSIBLE DEFENSE QUESTIONS AND SUGGESTED ANSWERS
--------------------------------------------------------------------
Q: What is a context diagram and why start with it?
A: It shows the entire system as one process with its external entities
   and the data crossing the boundary. It fixes the system scope before
   any internal detail, so every deeper diagram must stay consistent with
   it.

Q: Why are Tester and Guest Tester two separate entities if they do
   similar things?
A: The system treats them differently: a guest can run and watch a test
   live but nothing is saved, while a tester's runs can be saved and
   reviewed later. Separating them makes that difference visible at the
   top level.

Q: Is the Target Web App part of BugSafari?
A: No. It is owned by someone else. BugSafari only visits it, sends
   actions, and reads back what the browser sees, so it is an external
   entity.

Q: What happens if the AI Advisor is unavailable?
A: It is optional. Without an API key, BugSafari answers fix requests from
   a built-in catalog of known bug types, and everything else is
   unaffected.

Q: Why is the Email Service on the diagram at all?
A: It carries only password reset links during account recovery. It is
   external because it is a separate SMTP server, and it is drawn so the
   recovery flow is not hidden.

Q: Does a dropped connection lose data at this level?
A: The context diagram does not show that detail, but live progress and
   findings stream out to the tester; recovery of a dropped stream is
   handled inside the system, shown in the deeper diagrams.
